01

Install VS Code, Python, and uv

The baseline tooling for the course
Setup
01Install Visual Studio Code from the official site and add the code command to PATH.
02Use Python 3.13 for course work and verify the interpreter with python3 --version.
03Install uv and use it as the default project environment tool.
04Prefer uv venv and uv pip install for faster reproducible environments.
05Keep one workspace root per course project so settings stay local and predictable.
Outcome
A clean local Python toolchain ready for the bridge course and the AI engineering route.
02

Install the modern extension set

Python, Pylance, debugpy, Ruff, Jupyter, and GitHub tooling
Extensions
01Core language support: ms-python.python, ms-python.vscode-pylance, and ms-python.debugpy.
02Use Ruff for linting and formatting instead of deprecated python.linting.* settings.
03Add ms-python.black-formatter or charliermarsh.ruff depending on the project style.
04Install Jupyter extensions for notebooks and cell-based exploration.
05Add GitHub Pull Requests, Copilot, GitLens, and remote development packs as needed.
Rule of thumb
Install only the tools you actually use, and let the extension architecture stay modular.
03

Pick the interpreter and create the environment

Interpreter selection, .venv, conda, and uv
Environments
01Use Python: Select Interpreter to point VS Code at the active environment.
02Create a project .venv with either python -m venv or uv venv.
03Set python.defaultInterpreterPath in workspace settings when you want a fixed interpreter.
04Let VS Code detect requirements files and install dependencies after environment creation.
05Use Conda only when the project genuinely needs it; otherwise keep the setup simple.
Workspace trust
Keep trusted projects enabled so extensions, debugging, and linting activate as expected.
04

Workspace trust and security defaults

Protect untrusted folders and keep file execution visible
Security
01Trusted workspaces allow extensions that run code, lint, format, and debug.
02Use security.workspace.trust.untrustedFiles set to prompt in user settings.
03Be cautious with downloaded code and only trust sources you control.
04Keep secrets out of source control and use environment files for local values.
05Use repository-specific settings so the course setup stays reproducible across machines.
05

Editor settings and IntelliSense

The daily editing experience in VS Code
Editor
01Enable font, tab, wrap, and ruler defaults that fit Python code well.
02Turn on Pylance type checking and auto-import completions.
03Use inlay hints, sticky scroll, and bracket pair colorization for readability.
04Keep save-time actions focused: format, organize imports, and fix issues explicitly.
05Use the command palette for interpreter selection, sorting imports, and opening settings.
settings.json
{
  "python.defaultInterpreterPath": "${workspaceFolder}/.venv/bin/python",
  "python.terminal.activateEnvironment": true,
  "python.analysis.typeCheckingMode": "basic",
  "python.analysis.autoImportCompletions": true,
  "editor.stickyScroll.enabled": true,
  "editor.inlayHints.enabled": "on"
}
06

Linting and formatting

Ruff, Black, mypy, and flake8 as standalone tools
Quality
01Use Ruff for modern linting and formatting with a single config in pyproject.toml.
02Keep python.linting.* settings out of the project because they are deprecated.
03Install standalone tools like pylint, mypy, and flake8 only when the project needs them.
04Put formatter choice in the Python language block for consistent save behavior.
05Let the toolchain own import sorting, code actions, and line-length conventions.
07

Debugging with debugpy

Launch configs, breakpoints, and zero-config run
Debugger
01Use F5 to start debugging and Ctrl+F5 to run without debugging.
02Use debugpy in launch.json for modern Python debug configurations.
03Create launch entries for files, modules, web apps, pytest, and attach sessions.
04Use conditional breakpoints, logpoints, and hit counts when plain breakpoints are not enough.
05Use the call stack, watch expressions, and debug console to inspect runtime state.
launch.json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Run Current File",
      "type": "debugpy",
      "request": "launch",
      "program": "${file}",
      "console": "integratedTerminal"
    }
  ]
}
08

Testing with pytest and unittest

Discover, run, and debug tests from the editor
Testing
01Enable pytest discovery from workspace settings and keep tests under a clear folder.
02Use fixtures, parametrization, and short test names for readable test suites.
03Use the Testing panel for run, debug, and coverage-aware workflows.
04Keep unittest available for projects that depend on it or need mock.patch.
05Keep test config in pyproject.toml so discovery and coverage rules stay in sync.

Git, GitHub, Jupyter, tasks, snippets, profiles, and structure

Everything around the editor that keeps the course workflow clean
Workflow
01Use GitHub Pull Requests, Copilot, and GitLens to keep review flows inside VS Code.
02Use Jupyter notebooks and # %% cells for interactive Python work when needed.
03Create tasks for tests, linting, formatting, and dependency installs to reduce command drift.
04Build snippets for main guards, dataclasses, class skeletons, and test templates.
05Use VS Code profiles for separate course, data science, or web development environments.

Recommended project structure and checklist

Use one consistent layout for every course project
Reference
01Keep source code under src/ and tests under tests/.
02Keep pyproject.toml as the single source of truth for tool config.
03Add .gitignore entries for .venv/, .env, caches, and build output.
04Use .vscode/settings.json, launch.json, and tasks.json for workspace behavior.
05Verify the setup by opening a Python file, formatting, running tests, and starting the debugger.
